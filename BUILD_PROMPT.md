# Build prompt: Sleeper fantasy app for macOS

Paste the short kickoff at the bottom into Claude Code from inside this folder. This file is the full spec; keep it in the repo as `SPEC.md`.

## 1. What you are building

A native-feeling macOS desktop app (Electron) for Sleeper fantasy football. It runs year-round: offseason, pre-draft, draft day, in-season, playoffs. It supports **redraft** and **dynasty** leagues. It pulls everything from free public data. It never calls Claude, an LLM, or any paid service at runtime.

The owner is Krish, Sleeper username `krishd20`, league "fantasy" (`1392645750013329408`, 12 teams, full PPR, 3 divisions, 8-team playoff starting week 15, $1,800 FAAB). Use his league as the main test fixture, but nothing may be hard-coded to it.

The `reference/` folder holds a working in-browser version of the in-season model that was tested against live Sleeper data. **Port it; don't reinvent it.** Section 5 says what to keep.

### Non-negotiables
- No LLM or Claude calls at runtime. Every "take" or insight is generated by rules from real numbers, and every number on screen traces to a data source.
- Free data only (section 4). No scraping of sites whose terms forbid it (no KeepTradeCut, no PFF pages).
- Works offline from the last cache, with a clear "data as of" stamp everywhere.
- Unsigned, free `.dmg` (section 9). No Apple Developer account.
- Any Python you write for research, validation or data checks goes in **Jupyter notebooks (`.ipynb`), not `.py` files**. App code is TypeScript.
- Tests ship with every milestone (section 10).

## 2. Users, sign-in, and season phases

**Sign-in = Sleeper username.** Sleeper offers no third-party OAuth and apps can't verify passwords, so there is no password.
- First launch: a sign-in screen asks for a Sleeper username, checks it with `GET /v1/user/{username}`, then lists that user's leagues for the current season (and the previous season during the offseason).
- Remember the user and chosen leagues on this Mac. Allow several linked usernames and a quick switcher, so friends on the same Mac can use it.
- "Sign out" clears the remembered user and cache.

**Phase detection** drives the Home page and default tabs. Use `GET /v1/state/nfl` (`season_type`: `pre`, `regular`, `post`, `off`) plus each league's `status` (`pre_draft`, `drafting`, `in_season`, `complete`) and its draft's `status`.

## 3. Tech stack

- Electron (current stable) + Vite + React + TypeScript + React Router (one route per page).
- d3 for charts. No heavy UI kit; build components to the design system in section 8.
- **All network calls happen in the main process** behind a typed IPC layer (`contextIsolation: true`, `nodeIntegration: false`, preload bridge). That avoids CORS and keeps the renderer sandboxed.
- Storage: files under `app.getPath('userData')`. Raw downloads are kept gzipped; derived aggregates are JSON. **Avoid native Node modules** (no better-sqlite3), so the universal macOS build stays simple.
- Heavy parsing (the play-by-play CSV is about 5.5 MB gzipped per season) runs in a worker thread and produces per-player-week aggregates once per download.
- Season simulation runs in a Web Worker in the renderer, so the UI never freezes.

## 5. Model: port from `reference/`

`reference/sleeper_live.js`, `reference/ff_live.js` and `reference/fantasy_war_room.html` are a working, tested single-page version. `reference/sleeper_model.ipynb` is the offline research behind it. Port these behaviors into typed modules with unit tests:

- **Player means = Sleeper projection** scored with the league's own settings: PPR, half or standard by `scoring_settings.rec`, plus adjustments for passing-TD points and TE/WR/RB catch bonuses. In the offline bake-off on held-out weeks 4 and 5, projection MAE was 4.39, vs 4.43 for projection plus a GBM residual fix, 4.47 for shrink-to-season-average, and 4.68 for gradient boosting on form, snap share and matchup. Keep the projection and record this in the "How it works" page. Re-run this comparison in a notebook later in the season, when there are more weeks.
- **Floors and ceilings:** 20th and 80th percentile of actual÷projected points by position over the last four completed weeks (projection > 3). Fall back to the reference constants when there are fewer than 25 samples. Report held-out coverage (target 60%).
- **Matchup grades:** fantasy points each defense allows by position vs league average, from completed weeks. Soft is ≥1.15, tough is ≤0.87.
- **Current-week adjustments:** Questionable ×0.85, Doubtful ×0.3, Out/IR/Suspended ×0. IR players count again from four weeks out. Players whose game already kicked off use actual points and stay locked in their slot.
- **Lineup optimizer:** greedy fill of single-position slots first, then flex slots from most to least restrictive. Support QB, RB, WR, TE, K, DEF, FLEX, SUPER_FLEX, REC_FLEX, WRRB_FLEX and IDP slots from `roster_positions`.
- **Season simulation:** 20,000 runs. Weekly team score is normal around the best lineup's expected points, with sd = √(Σ per-slot residual variance) (about 19 to 21 points in this league), ×0.85 for the in-progress week. Seeding: division winners first, then wildcards by wins with points-for as tiebreak. Read `playoff_teams` and `divisions` from settings; with zero divisions, seed by record only.
- **Strict clinch math:** port `designations()` and `winsToClinch()` from `ff_live.js` as is, including the rule that division winners don't use wildcard spots. Marks: x clinched spot, y clinched division, d out of the division race, e eliminated. A mark must never appear unless it's mathematically guaranteed.
- **Waiver gain:** points added to the best lineup over a window (rest of season, next week, playoff weeks) after dropping the cheapest bench player; FAAB bid scaled to the remaining budget.
- **Trade analyzer:** re-score both best lineups for the rest of the regular season and the playoff weeks, re-simulate, and show the change in playoff odds. Win-win 1-for-1 ideas ranked by the smaller of the two gains.
- **Regression test:** with the fixture snapshot in `reference/fixture/` (create it on first run by saving one full pull of league `1392645750013329408`), the ported engine must reproduce the reference engine's playoff odds within ±1.5 points per team and the same top-3 waiver adds.

### New derived stats (per player-week and season-to-date)
From pbp, snaps and FTN (2026), joined by `gsis_id`:
- Snap share; target share (targets ÷ team pass attempts); air-yards share; aDOT; WOPR (1.5 × target share + 0.7 × air-yards share); yards per target; catch rate vs catchable targets.
- Red-zone and inside-10 target and carry share; end-zone targets; expected-TD gap (TDs vs a simple yardline-based expected-TD model you fit in a notebook).
- RB: rush share, yards per carry vs stacked boxes (≥8 in box) vs light boxes, targets per route proxy (labeled).
- FTN splits: production vs blitz/no blitz, play-action share, screen share, contested-catch rate, drop rate.
- 2025 (labeled): yards per route run, targets per route run, and the same vs man and vs zone, from participation `route` and `defense_man_zone_type`.
- Every split shows its sample size. Hide splits under a minimum (for example, fewer than 15 targets or 20 routes).

## 6. Pages

Each page is its own route with a sidebar. Every page shows "data as of" and has a Refresh button.

1. **Sign in.** Username, league picker, linked accounts.
2. **Home.** Changes by phase:
   - *Offseason:* dynasty value movers, rookie class, your roster's age profile, league history.
   - *Pre-draft:* countdown to the draft (from `/drafts` `start_time`), your draft slot, a "prep checklist" with tiers to study and mock-draft results.
   - *Draft day:* jumps to the live draft assistant.
   - *In-season:* playoff odds and status (clinch marks), this week's matchup, lineup alerts, top 3 waiver adds, injury flags, and the top takes for your players.
3. **Takes** (the feed; section 7).
4. **Players.** Search all players. Profile pages show a game log, usage trends (snap %, target share, air yards, red zone), FTN splits, 2025 coverage and route splits, next 4 opponents with matchup grades, projection with floor and ceiling, redraft rest-of-season value, dynasty value and its 30-day trend, and an "Add to watchlist" button.
5. **My team.** Roster with usage and value, lineup for any week with pin/bench, what-if lab (return week, points-per-game overrides, add/drop), weekly projection chart.
6. **League race.** Standings with all-play record and luck, playoff odds, division odds, seed heatmap, wins-needed chart, team detail drawers, and the **playoff machine** (pick game winners; standings and clinch marks update).
7. **Waivers.** Live gain by window, FAAB bids, trending adds, usage risers.
8. **Trades.** Analyzer (any number of players per side), win-win ideas, and dynasty mode (FantasyCalc values, future picks from `traded_picks`, "contender vs rebuilder" lens).
9. **Draft.**
   - *Rankings:* season projections scored with league settings → value over replacement using the league's starting slots → tiers by natural gaps. ADP from the matching Sleeper field (`adp_ppr`, `adp_half_ppr`, `adp_std`, `adp_2qb`, or the dynasty and rookie variants).
   - *Mock draft:* you pick at your real slot, bots draft by ADP plus noise and roster need, and the grade at the end compares projected starters to the league.
   - *Live assistant:* when the league draft's `status` is `drafting`, poll `/v1/draft/{id}/picks` every 3 to 5 seconds. Show best available by VOR and tier, positional runs, your needs, and value vs ADP on every pick.
   - *Dynasty:* startup draft uses dynasty ADP and FantasyCalc values; rookie drafts use `adp_rookie` and FantasyCalc rookie values.
10. **Settings.** Linked accounts, refresh schedule (auto-refresh on open if data is older than 6 hours; players file at most daily), cache size and clear, Data health (unmatched IDs, endpoint checks), attribution, about.

## 7. Takes feed

A short-form feed in the voice of a sharp fantasy content creator: quick, specific, numbers-first. **Rule-based templates only, no LLM.** Each card has:
- A headline of 12 words or fewer, plain and punchy, with no hype words.
- One stat line with the actual numbers, the comparison, and the sample size.
- A "why it matters for you" line when the player is on one of your rosters, on waivers, or on a trade target.
- Actions: open the profile, watchlist, or try it in the what-if lab or trade analyzer.

Start with these detectors (tune thresholds in a notebook against 2025 data, and include the notebook):
- **Usage spike:** snap share up 15+ points vs the previous 3-week average.
- **Target hog:** target share at least 25% over the last 3 weeks.
- **Buy low:** air-yards share in the top 24 at the position but fantasy points per game outside the top 36.
- **Sell high:** TDs at least 2 above expected TDs.
- **Red-zone role change:** inside-10 share up or down sharply.
- **Box-count edge:** RB yards per carry vs light boxes paired with an opponent that plays light boxes often.
- **Blitz beater:** WR or TE production vs blitz well above their baseline, facing a high-blitz defense next.
- **Soft schedule ahead:** next 3 matchup grades all soft.
- **Waiver riser:** trending adds plus a usage increase.
- **Dynasty mover:** FantasyCalc 30-day value change in the top or bottom 5% (dynasty leagues).
- **Coverage note** (labeled 2025 until 2026 participation exists): big yards-per-route gap between man and zone, matched to the opponent's tendency.

Rank cards by relevance (your players first, then waiver and trade targets, then league-wide). Show no more than 3 per player per week.

## 8. Design system (use exactly)

Editorial and utilitarian, not playful.
- Background parchment `#f4f1eb`, raised panels `#faf8f3`, ink `#1f1d19`, secondary text `#5d5850`, muted `#8a8478`, rules `#dcd5c6`.
- Accents: green `#2d5a27` (good, primary actions), warm red `#8b3a1a` (bad, risk), gold `#c4922a` (watch, wildcard).
- Type: DM Mono for the body, Instrument Serif for display headers and big numbers, italic serif for section titles, uppercase micro-labels with letter-spacing. Bundle both fonts in the app (both are SIL Open Font License) so it works offline.
- Minimal borders, border-radius 3px max, clean thin progress bars, checkbox tasks with line-through when done, tabular numbers.
- Motion: subtle number count-ups, bar growth, page fades; respect "Reduce motion".
- Look at `reference/fantasy_war_room.html` for the established look and copy its patterns.

## 9. Packaging (free, unsigned)

- electron-builder, `mac.target: [{ target: 'dmg', arch: ['universal'] }]`, `mac.identity: null` (unsigned), no notarization. App name "War Room", generic football icon (draw your own; no NFL or team marks).
- `npm run dist` produces `dist/War Room-<version>-universal.dmg`.
- Add a `FIRST_OPEN.md` and an About-screen note. Because the app is unsigned, macOS blocks the first launch. On recent macOS, open System Settings → Privacy & Security and click "Open Anyway" for War Room. Fallback: `xattr -dr com.apple.quarantine "/Applications/War Room.app"`.
- Updates: a menu item "Check for updates" that compares the version against a `version.json` path the owner can set later. No auto-updater for now.
